# 研数 · 考研数学 AI 自学系统

根据《考研数学AI自学系统开发文档 v1.0》实现的**单人本地 MVP**：每天和 AI 老师聊着学完知识点，智能出题验收，答错的题自动进错题本并按 SM-2 间隔重复调度复习，每日任务 + 专注计时自动打卡。还能开一节**多智能体课堂**——一个老师带三个水平不同的学生，四个人各自独立调用模型。

技术形态：**纯前端多文件应用**（原生 JS + CSS，零构建、零依赖、零后端）。

## 快速开始

**方式一：直接双击**（推荐，完全离线可用）

打开 `index.html`，浏览器以 `file://` 协议运行，所有数据存本机浏览器 localStorage。

> 数学公式默认走 KaTeX CDN，无外网时自动降级为高亮原文显示，不影响功能。
>
> **默认接云端 API（DeepSeek）**，`file://` 下也能用——去设置页填一个 Key 就行。
> 想改用本地大模型（LM Studio / Ollama）请用方式二，`file://` 协议下浏览器会拦截对 `localhost` 的请求。

**方式二：本地服务器**

```bash
cd kaoyan-math-tutor
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080
```

**方式三：GitHub Pages 在线部署**

本仓库可直接推送至 GitHub 并开启 GitHub Pages（Settings → Pages → Branch **`master`** / folder `root`），
即可获得免费在线访问地址，手机/平板无需安装即用。

线上地址：<https://111wukong.github.io/kaoyan-math-tutor/>

> 推完 `master` 之后 Pages 会自动 rebuild（约 40 秒）。**别用 `curl` 判断部署成没成** ——
> 它只能证明文件在服务器上，证明不了页面跑得起来。用 `node tests/smoke-online.js` 开真浏览器验一遍。

## 打卡规则

满足其一即视为当日打卡成功（进入连续天数与热力图统计）：

- 今日任务单 3 类任务全部完成（复习卡全评 + 新知识点全验收 + 每日一练全作答）
- 专注计时累计 ≥ 30 分钟

## 数据资产：stats 是权威，attempts 只是明细

这个应用没有服务端，localStorage 是唯一的持久化介质。原来的实现有三处硬伤：

1. `save()` 把写入异常整个吞掉 —— 配额满了用户毫无察觉，一直答到某天发现进度没了；
2. `state.attempts` 只增不减。按每天 50 题算，一年 1.8 万条 ≈ 2.3 MB，而浏览器配额通常 5 MB；
3. 没有任何导出出口，浏览器清缓存 = 全部学习记录归零。

第 2 条看着像"加个裁剪就行"，其实不能直接裁 —— **掌握度的口径是「该节点下每道题都答对过」**，
它依赖完整历史。裁掉明细就等于裁掉掌握度。

所以拆成两层：

| | 作用 | 生命周期 |
| --- | --- | --- |
| `state.stats` | 全量聚合。掌握度、正确率、热力图、薄弱点、备考投影**全部**读它 | 永不裁剪 |
| `state.attempts` | 明细。只服务"展示某次作答原文"这类需求（错题本的「我的答案」） | 保留最近 2000 条 |

关键不变式：**裁剪之前先把全量计数冻结进 `stats`**。顺序反了就会真的丢数据 ——
`tests/test-store.js` 第一段就是断言「裁剪前算出的掌握度 / 正确率 / 错题数 / 逐日统计，与裁剪后完全一致」，
并且做了变异测试验证（把 `trim()` 里两段的顺序调换，8 条断言立刻报错）。

由此带来一条硬规矩：**任何消费方都不允许绕过 `Store.statsOf()` 自己去遍历 `attempts`。**
`Game.nodeMastery` / `Game.snapshot` / `Game.answerXp` / 仪表盘 / 统计页 / 给 AI 的工具上下文
全都改成了读聚合。测试里有一条对照断言专门钉住这件事：

```
裁剪后 statsFrom(s).n === 2000   // 只数明细 —— 所以不能用它
裁剪后 statsOf(s).n  === 5200    // 权威聚合 —— 用它
```

配套的三件事：

- **写盘失败必须被看见**：`save()` 返回成败，失败时弹一次 toast + 挂一条常驻底部横幅（横幅里直接给「导出备份」按钮）。
  隐私模式下一进页面就会提示"这次会话的进度不会被保存"。
- **导出/导入**：设置页「数据与备份」一键导出 JSON（**默认剥掉 API Key**，因为导出文件常被丢进网盘和聊天窗口）。
  导入支持「合并」与「覆盖」两种；合并的策略是**只增不减** —— 作答按 id 去重取并集、卡片取复习进度更靠后的那次、
  XP 取更大的、成就取并集。覆盖导入会保住本机的模型配置，换台机器导入不会把 Key 冲掉。
- **用量可见**：显示存档体积、明细条数、累计次数、覆盖天数，以及实测的配额占用比例（探针实测，不编一个假数字）。

## 可观测性：没有服务端，也不能什么都不知道

用户说"它坏了"的时候，开发者手上什么都没有 —— 连"他打开的是哪个页面、报了什么错"都不知道。

`js/telemetry.js` 把事件与错误留在本机（独立的 localStorage key，不污染主存档，可单独清空），
设置页「诊断」里可以一键复制或导出。全局捕获三类：JS 异常（带出错位置）、未处理的 Promise 拒绝、
以及**资源加载失败**（「KaTeX CDN 挂了」和「JS 抛异常」是完全不同的两件事，混在一起没法排查）。

一条硬规则：**诊断包里不出现任何用户内容**。

不包含 API Key、聊天记录、笔记正文、题目与答案、错题原文 —— 只有环境信息、计数和错误消息。
用户愿意把诊断包发给你，不等于愿意把跟 AI 的对话记录一起发给你。
`tests/test-telemetry.js` 第 1 段就是拿一份"处处是敏感内容"的 state 生成报告，逐项检查里面找不到它们；
变异测试验证过（让 `report()` 把原始事件打出来，断言立刻报"泄露了 sk-LEAK-CANARY-9931"）。

模块里留了 `endpoint` 字段但默认空着。将来接服务端改这一处即可，但**不要默默打开** ——
一个承诺"数据不出本机"的应用突然开始上报，是信任层面的事故。

## 小屏与无障碍

考研学生大量用手机刷碎片时间，而原来的窄屏规则只是把侧栏从 216px 缩到 176px ——
在 375px 的手机上仍占掉一半屏幕。现在 ≤820px 时侧栏收成抽屉（默认移出视口，点左上角滑入，
带遮罩、锁背后滚动、Esc 可关、Tab 只在抽屉内循环），主内容占满屏宽。

无障碍此前几乎是零（全站 1 处 `aria-hidden`、`alt` 0 处）。现在：

- 键盘第一个 Tab 就是「跳到主要内容」（用 `<button>` 而不是 `<a href="#main">` —— 本应用的路由就是 hash，锚点会把路由带跑偏）
- 全站 `:focus-visible` 焦点环（鼠标点击不出环，键盘导航必须有）
- 侧栏图标统一 `aria-hidden`（把描边属性提到顶层 `.ic`，顺带修掉了小屏导航按钮和音效开关图标隐形的问题）
- 图表给读屏器配文字摘要：折线图报"有记录 N 天，最低 x%，最高 y%"，雷达图逐个念科目正确率
- 答题反馈区 `role="status" aria-live="polite"`，答完当场播报对错
- 小屏触摸目标一律 ≥40px

这些都由 `tests/test-browser.js` 在真实无头 Chromium 里断言（含 375×812 的设备模拟），不是靠自觉。

## AI 老师：Agent 内核

聊天页的 AI 不是"关键词匹配 + 写死模板"，而是一个带工具的 agent loop。

**它能看到什么**：每次对话前，系统从 localStorage 实时算出你的学情并注入提示词——已掌握/学习中/未开始考点数、连续打卡天数、近 7 天正确率、最薄弱的几个考点及错误次数、当前考点的作答历史与待攻克错题。模型据此决定讲什么、讲多深。

**它能做什么**（14 个工具，全部读写你的真实数据）：

| 工具 | 作用 |
| --- | --- |
| `query_weakness` | 查最薄弱的考点排行 |
| `get_mistakes` | 翻错题本（答错且尚未做对的题） |
| `pick_question` | 按知识点 + 难度加权抽题 |
| `get_node` | 读某个考点的完整正文与关联考点 |
| `search_nodes` | 按关键词检索知识树 |
| `get_progress` | 读整体进度、打卡、距考试天数 |
| `draw_graph` | **把函数画成图像直接显示**（讲极限/单调性/凹凸性/面积时）；表达式带参数时还会**长出滑块**，学生拖着自己看曲线怎么变 |
| `write_steps` | 把解题步骤一步步写到黑板上 |
| `write_latex` | 把公式排到黑板上（KaTeX 渲染） |
| `highlight` | 圈出黑板上已有的某一处 |
| `clear_board` | 擦黑板 |
| `new_page` | **翻到新的一页**（前面写的留着，学生能翻回去看） |
| `save_note` | 把总结记到考点下 |
| `mark_mastered` | 标记已掌握并生成复习卡片 |

后 5 个（`write_steps` / `write_latex` / `highlight` / `clear_board` / `new_page`）是**黑板动作族**，聊天页和课堂页共用同一份工具表——详见下面[「黑板：一串动作，不是一张图」](#黑板一串动作不是一张图)。

`draw_graph` 配了一个自写的递归下降表达式求值器（**不使用 eval**），支持 `+ - * / ^`、括号、隐式乘法（`2x`、`3sin(x)`）、`sin/cos/tan/ln/log/exp/sqrt/abs` 等函数与 `pi`、`e` 常数，输出纯 SVG 曲线，无图表库依赖。

它还支持**带参数的表达式**：写 `a*x^2+b*x+c`，并在 `params` 里声明 `a`、`b`、`c` 的取值范围，图上就会长出滑块——学生拖着就能看曲线怎么变。讲「参数对图像的影响」时，这比连画三张静态图清楚得多，而且结论是他自己拖出来的。有两个不显眼但很要紧的地方：

- **y 轴范围要预先算好并钉死**。工具层让每个参数各取遍自己的 `min` / `max` 端点、把结果并起来求**包络**，重绘时复用同一个范围。否则坐标轴会跟着参数一起缩放，整张图随手指抖，反而看不出参数到底改变了什么。
- **x 轴范围也要一起存进黑板块**（`xmin` / `xmax`），不然重绘会退回默认的 `-2π~2π`，跟老师原本要讲的那段区间对不上。

参数名有限制：单个字母、不能叫 `x`、不能撞内置常数（`pi`/`e`/`tau`）或函数名（`sin` 等），最多 3 个——这些在**编译期**就校验，写错了当场报错，而不是画到一半返回一张空图。

**四种老师人设**（设置页切换，同一内核的不同提示词策略）：严格督学 / 段子手 / 苏格拉底 / 应试机器。

**模型通道**（设置页分段切换，默认**云端**）：

- **云端 API（默认）**：开箱预填 DeepSeek（`https://api.deepseek.com` + `deepseek-chat`），也兼容任何 OpenAI 协议服务（Kimi / 通义 / 自建网关）。**去设置页填一个 Key 即可开聊**，无需任何本地环境。
  Key 默认只存内存，刷新页面需重填；想省事可勾「记住 Key」（写入本机 localStorage，**明文**——只在自己电脑上勾）。
- **本地模型**：设置页点"探测本机"自动扫描 LM Studio（1234）、Ollama（11434）、vLLM（8000）、llama.cpp（8081）。免 Key、离线、数据不出本机。

> 两条通道的配置**各存一份、互不覆盖**：切到云端不会清掉你的本地模型名，切回本地也不会丢掉云端 Base。

**两条健壮性保障**：

1. 模型不支持原生 `tools` 参数（本地小模型常见）时，自动降级为**文本工具协议**（` ```tool ` 代码块），不必换模型。
2. 模型完全不可用时，静默降级回内置教学引擎，聊天不中断。

> **注意**：默认的云端通道在 `file://` 下可直接用。只有改用**本地模型**时才需要方式二——`file://` 协议会拦截对 `localhost` 的请求，请在该目录执行 `python3 -m http.server 8080` 后访问 `http://localhost:8080`；LM Studio 需在 Server 设置中开启 CORS。

### 「测试连接」失败怎么排查

点「测试连接」会先问 `/models` 拿模型列表；若该地址没有这个接口，会自动改发一次**最小对话请求**来判定——因为真正要回答的问题是「能不能对话」，而不是「有没有 `/models`」。

失败提示会**按原因分开**，别混着看：

| 提示 | 含义 | 怎么办 |
| --- | --- | --- |
| `已连通，但鉴权没过` | 网络通了，Key 被拒（401/403） | 检查 Key 是否复制完整、有无多余空格、是否欠费 |
| `连不上` | 压根没建立连接 | 查网络 / 代理 / 防火墙；确认接口地址没填错 |
| `连接超时` | 建立了连接但没响应 | 云端查网络；本地看模型是否还在加载 |
| `返回的不是 OpenAI 兼容接口` | 连上了但响应不是 JSON | 接口地址应填**根地址**（如 `https://api.deepseek.com`），不要带 `/chat/completions` |
| `接口能连上，但模型列表里没有「X」` | 连得上，模型名写错了 | 按提示里列出的可用模型名改 |

> 提示语本身也**认通道**：云端地址不会让你去「启动本地推理服务」，本机地址也不会让你去「检查 API Key 余额」。

## 课堂：老师 + 三个真 agent

在知识点页进「课堂」，换一种学法。四个人**各自独立调用模型、各自有记忆、各自有工具**——不是一次批量生成出来的四段台词。

### 两种模式

| 模式 | 流程 | 适合 |
| --- | --- | --- |
| **课堂模式** | 老师讲第 1 步 → **你先动手复述/试做** → 老师针对你答的给最小提示 → 学生讨论、老师答疑 → 讲第 2 步 → … → 老师小结 → **换一道同类新题给你独立做** → 讲评 | 第一次学这个考点 |
| **讨论模式** | 老师抛一道你做错过的题 → **你先答** → 三个学生互怼 → 老师点名点评谁对谁错在哪一步 → **换一道同类新题给你独立做** → 讲评 | 已经学过但老是做错 |

两种模式里你**都不是观众**。中间有一道硬闸：**你没交答案之前，谁也不许说答案**。老师会停下来等你，等到了才继续往下走。

课堂模式的「提问讨论」环节是重点：老师讲完一步，学生可以 `raise_hand` 举手，举手会**打断调度**——下一个发言的必然是老师，先答疑再继续。三个学生也会互相接话。

### 你不动手，这节课就不往下走

这是整块课堂最要紧的一条。之前的做法是「四个 agent 聊得热闹，你在旁边看」——那本质上是**一档节目**，不是学习。现在课堂会在两个地方**停下来等你**：

| 停在哪 | 提示什么 | 你交完之后 |
| --- | --- | --- |
| 讲完第 1 步之后 | 「这一步你能用自己的话复述一遍吗？或者直接往这道题上套一下。」 | 老师按你答的内容分三种情况回应：**答对了**往下走、**答错了**只给最小提示、**跳过了**也不硬讲 |
| 全部讲完 / 点评完之后 | 「这道新题你自己做，做完再说。」 | 老师讲评，并把这道新题记进你的记录 |

顺序是刻意排的：**先你想过，再听别人说**，才有对照；反过来就只是听热闹。

等答案期间，插话和举手入口是**关掉**的——你此刻该做的是交答案，不是同时开两条线让老师顾不过来。不想答可以点「先跳过」，课堂照常继续，但这次就没你的输入了。

### 三条硬规则

这三条写死在老师的系统提示里，不是「建议」：

1. **用户没交答案之前，不许说出答案**——包括不许换个说法暗示。
2. **答错了先给最小提示，不要直接把解法讲完**——留一步让他自己走。
3. **他答完之后，必须出一道同类型的新题让他独立做**——答对不等于学会，换一道才算。

第 3 条就是「最近发展区」（ZPD）里那个验证环节：**独立尝试 → 最小提示 → 再试一次 → 新题独立作答**。少了最后一步，「我懂了」永远只是一句感觉。

第 1 条连**答疑**都管着：学生举手把老师叫回来答疑时，老师可以讲透概念，但**只要你自己还没答过这道题，仍然不许报出这道题的答案**。举手是逃生门，不是抄答案的后门。

### 差异不是靠形容词，是靠机制

如果只在提示词里写「你是一个基础薄弱的学生」，模型会趋同——三个人说出同一种 AI 腔。真正的差异化靠两件事：**知识边界不同**、**错法不同**。

| 角色 | 系统提示里拿到什么 | 调 `look_up` 能查到什么 | 他的错法 | 典型表现 |
| --- | --- | --- | --- | --- |
| 学生甲（思路快） | 完整正文 + 例题 + 关联考点 | 全部 | **结论下得太早**——方法对，但不验边界条件 | 一针见血，爱把规律总结成一句话 |
| 学生乙（中等） | 正文 + 例题 | 正文 + 例题 | **条件用错了**——记得公式，但搞错它成立的前提 | 跟得上，但爱追问"为什么" |
| 学生丙（基础薄弱） | **只有第一句定义** | **也只有第一句定义** | **概念混淆**——把两个相邻概念当成一件事 | 口语化、用错术语、想当然 |

第三列是关键：丙就算主动调工具去查资料，也只能查到那一句。这是**结构性无知**，不是演的——提示词拦不住模型"自由发挥"，但数据源可以。

第四列是「**三个人都会犯错**」。以前只有丙会错，甲和乙永远正确，看着像陪读。现在三个人各绑一种典型失误，而且**一道选择题的干扰项会按水平分给三个人**——干扰项够多就一人一个、谁也不重复，不够分才复用。所以你会看到三种不同的错法撞在一起，而不是三个人说出同一句废话。

**而且学生拿不到正确答案。** 干扰项是当作「一个真实的错误思路」给他们的，选项里没有对的；三个人的错法还各不相同。谁对谁错要靠他们自己吵出来——**老师也不许提前公布**。

### 黑板：一串动作，不是一张图

以前黑板上只有一种东西——函数图像，而且是**一次性铺上去**的。现在黑板是**一串按序发生的动作**，谁写、写了什么、什么时候写的，都在上面。

| 动作 | 谁会用 | 效果 |
| --- | --- | --- |
| `draw_graph` | 老师 + 学生 | 画函数图像。曲线会**从左到右描出来**，不是啪一下出现；表达式带参数时还会长出**滑块**，学生拖着看曲线怎么变 |
| `write_steps` | 只有老师 | 写解题步骤（标题 + 最多 8 条），**逐条错开 140ms 落下来** |
| `write_latex` | 只有老师 | 写公式，可附一句说明。`$` / `$$` 定界符会自动剥掉 |
| `highlight` | 老师 + 学生 | 圈出黑板上已有的某一块——按文字匹配，不是按坐标 |
| `clear_board` | 只有老师 | 擦黑板，之前画的全作废 |
| `new_page` | 只有老师 | 翻到新的一页。**前面写的留着**，学生能翻回去看 |

几个刻意的设计：

- **学生不能写完整解答。** `write_steps` 和 `write_latex` 只给了老师。学生只能画图、圈重点——**会画图不等于会写解法**，这条线不能糊。
- **`highlight` 不算一块内容。** 它是打在已有块上的光，不是新东西。所以黑板块数记账时它不占号（`data-blocks` 只数真正画出来的块）。
- **只有新追加的块播动画。** 黑板是整块重画的，如果不管新旧，每加一行都会让整块黑板重播一遍入场动画——看着像在抽搐。所以渲染时把「已经画了几块」记在 DOM 上（`data-blocks` / `data-clear`），只有超出这个数的才带 `.c-fresh`。
- **擦过黑板就重新算新。** `clear` 之后剩下的全部带入场动画，因为对眼睛来说它们确实是刚出现的。
- **翻页不播动画。** 翻页时屏幕上是换了一批内容，但那是**他自己翻的**——拿一屏入场动画糊他脸只会显得卡。所以页号也记在 DOM 上（`data-page`），页号一变就把「新块起点」推到末尾。

#### 分页：翻页是保留，擦黑板是作废

一节课要讲好几件事。没有分页时，讲到第三个知识点，第一个已经滚出视野了，要回头看只能一路往上翻。

页号**不存进数据**，而是在动作序列里插一个 `{kind:'page'}` 分隔块，页号由渲染层数出来。这么做的直接好处是**老存档零迁移**——没有分隔块的记录天然就是一页。另一个好处是「第几页」永远只有一个真相来源，不会出现块上的页号和实际位置对不上。

两条规则值得写下来：

- **`new_page` 和 `clear_board` 是两件事，别混。** 前者是「讲完了，翻一页」，后者是「写错了，擦掉」。混用的代价是学生翻回去发现内容没了——而翻回去看正是分页存在的意义。
- **只有一页时不渲染导航。** 一节课没翻过页，就别多给他一个要理解的东西。
- **翻页位置只在内存里。** 刷新后回到最新一页是更合理的默认——他关心的是老师刚写了什么。
- **`prefers-reduced-motion` 下动画全关**，而且必须同时把 `stroke-dasharray` 也清掉——描线动画靠虚线偏移实现，动画一停虚线状态会把曲线**整条藏起来**。
- **拖滑块不重播入场动画。** 重绘时只换图容器，并先把这一块的 `.c-fresh` 摘掉。否则新插进去的 `<path>` 会重新匹配那条描线规则，每拖一下就重播一次「一笔描出来」——那是入场动画，不是交互反馈。语义上也对：他都在拖它了，它显然不再是「刚出现的块」。

「一笔一笔写出来」和「啪一下全出现」信息量完全一样，但只有前者有节奏。黑板如果只是个展示区，看两眼就走了；有节奏才像有人在旁边写。

### 谁决定下一个谁说话

借了 [OpenMAIC](https://github.com/THU-MAIC/OpenMAIC)（清华，37k★）的 director graph 思路，但做了成本裁剪——**先本地规则短路，只在歧义回合才问模型**：

1. 有人举手 → 老师，直接定，不问模型
2. 还有人没开过口 → 按优先级让他开口，不问模型
3. 说到量了 → 结束，不问模型
4. 都不满足 → 才调一次调度器，让它返回 `{"next": "agent_id" | "END"}`

调度器挂了也不影响上课——退回轮转，绝不因为调度失败让整节课中断。

### 记忆

每个学生只记自己的：自己说过的话（去重、上限 4 条）+ **老师点名点评到自己的那几句**。老师点评里出现「学生丙」，那句话就自动进丙的记忆。下一轮他开口时会看到「老师点评到我：……」。

### 成本

| 环节 | 调用次数 |
| --- | --- |
| 老师每次发言 | 1 次（流式） |
| 三个学生首轮 | **3 次并发**（墙钟时间等于 1 次） |
| 后续每轮学生 | 1 次 |
| 调度器 | 仅歧义回合 1 次 |
| 学生 agent loop | 上限 2 步（调工具 → 出结论） |
| **停下来等你作答** | **0 次**——纯本地等待，不花一分钱 |

一场课堂模式（2 步讲授）约 **11-14 次调用**，讨论模式约 **15-19 次**（后者讨论轮数更多，还常被举手打断出额外的答疑回合）。云端约 30-60 秒，用逐字打字掩盖等待。

> 让你作答这一步是**免费的**，而且是整块课堂里唯一真正产生学习的一步。之前那版没有这一步——省下的那几次调用并没有换来效果，那才是真的浪费。

> 想省钱就少开课堂，多用聊天页——聊天页一场只花 1-2 次。

### 学生能用的工具（白名单）

| 工具 | 作用 |
| --- | --- |
| `look_up` | 翻书查当前考点——**查到的内容受水平限制** |
| `recall_mistake` | 回忆自己做错过的题（只给题干和错次，**不给答案**） |
| `draw_graph` | 在黑板上画函数图像 |
| `highlight` | 圈出黑板上已有的某一处（**只能圈，不能写**） |
| `raise_hand` | 举手，要求老师先答疑 |
| `pass` | 这轮不说了（弃权） |

学生**不能**标掌握、不能记笔记、不能改你的学情数据，也**不能写完整解答**——`write_steps` / `write_latex` 不在他们的白名单里，`new_page` 也不在（翻页是老师安排课堂节奏的动作，学生要回头看得靠前端那个导航按钮）。`STUDENT_SCHEMA` 是独立白名单，跟老师的 **14 个**工具分开。

这条边界由测试守住：`test-agent.js` 里有一节专门断言学生**拿不到**写完整解答的工具——不然「学生 agent」迟早会退化成第二个老师。

### 老师的教学动作能算出来

老师每次发言的**第一行**要写一个标签，说明这段话属于哪种教学动作：

| 标签 | 含义 |
| --- | --- |
| `(focus)` | 把注意力拉回关键处 / 推他自己往下走 |
| `(probing)` | 追问，逼他把话说清楚 |
| `(telling)` | 直接告知（讲答案、给结论） |

标签在流式输出时就**被剥掉**了，你不会在屏幕上看到孤零零的 `(focus)`；但它被记进了 `session.moves`，侧栏那张「老师的教学动作」卡片会算出**引导占比**：

```
引导占 71%  ███████░░░   追问 3 · 告知 2
```

这件事的意义在于：**「这节课到底是在引导还是在念答案」从一句感觉变成了一个数字。** 好课是引导为主；如果引导占比长期很低，说明老师（也就是模型）在偷懒直接讲答案，那三条硬规则没被遵守——你能当场看出来，而不是听完整节课才觉得「好像哪里不对」。

标签被剥掉这件事也有测试守着（`parseMove` 的大小写不敏感 + 流式路径），否则第一个 token 就会把 `(foc` 这样的半截标签漏给用户。

### 借鉴的开源项目

| 项目 | 借了什么 |
| --- | --- |
| [THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC) | director graph（调度器返回 `next` / `END`）、发言状态机、**「动作 + 时序」这个思路**（它的黑板有 21 种动作、每种配时长常量） |
| [Ljyustc/SocraticLM](https://github.com/Ljyustc/SocraticLM) | 「教导主任-教师-学生」多角色数学教学流程（中科大 + 讯飞） |
| [Stanford Generative Agents](https://github.com/joonspk-research/generative_agents) | 记忆流：只记与自己相关的、去重、有上限 |
| [eth-nlped/mathdial](https://github.com/eth-nlped/mathdial) | 教学动作分类法（`focus` / `probing` / `telling`）——「引导还是告知」由此可量化 |
| [plastic-labs/tutor-gpt](https://github.com/plastic-labs/tutor-gpt) | 心智理论（ToM）：老师要建模「这个学生现在知道什么」，而不是照本宣科 |

> 抄的是**机制**，不是规模。OpenMAIC 有 21 种黑板动作和一整张时长常量表；这里只挑了 6 种，用 CSS 动画实现——同一件事，成本差两个数量级。
>
> 另外，**「学生答错之后老师怎么办」这件事 MathDial 做得最细**：它把老师的每一句话标成 `focus` / `probing` / `telling`，还专门统计一个叫 `self-correctness` 的指标——其中有一档叫「对，但我不得不把答案说出来了」。这个「不得不」就是三条硬规则要防的东西。

### 选题优先级

错过次数最多的题 → 正确率最低的考点里抽一题 → 当前考点随机一题。

## 卡片库：把一节课变成能打印的复习卡

课堂上聊完的东西，关上页面就忘了。卡片库把它压成**能揣兜里、能贴墙上**的复习卡。

课堂页点「整理成复习卡片」→ 卡片库（左侧导航也有一项，跨考点汇总）。

### 六类卡片

| 类型 | 正面 | 背面 | 从哪来 |
| --- | --- | --- | --- |
| **题目回顾** | 题干 | 答案 + 思路 | 这节课讨论的那道题 |
| **必记结论** | 结论本身 | —— | 老师最后一段小结里的编号列表；没编号就按关键词抽句 |
| **解题步骤** | 题块标题（如「求 lim (tan x − sin x)/x³」） | 编号好的步骤 | 黑板上的 `write_steps` |
| **易错点** | 老师点名的原句 | —— | 老师点评里**点到学生名字**且含「错 / 混淆 / 不能」的句子 |
| **疑问解答** | 学生的问句 | 老师随后的回应 | 学生发言里的问句 + 下一个老师回合的头两句 |
| **必记公式** | 公式 | **它出现的那句话**（没有就留空） | 题目解析、老师发言、黑板 |

必记结论优先抽**编号列表**（老师自己已经归纳过了），没有编号才退回关键词匹配——
让老师的话原样变成卡片，比我重新组织一遍可靠。

### 公式卡有一道闸

这段数据里 `$...$` 大量用于正文里的行内数学（`$\sin x$ 等价于 $x$`）。第一版直接把每个
`$...$` 都做成公式卡，结果 15 张卡里有 5 张是 `x^3/2`、`1/2`、`\sin x` 这种碎片——
**这不是公式，是句子的零件**。

现在的判据分三层，关键是**别把「符号」当成「结构」**：

1. **含等号** → 是结论式，直接认（`a^2+b^2=c^2`）
2. **含结构命令** → 是个式子（`\frac` `\lim` `\int` `\sqrt` `\sim` …）
3. **只有单个符号** → 得够长才算（`\to` `\infty` `\leq` …）

第 2、3 层还都要求**含变量**——光有数字和符号的片段不是公式。这条约束是后来补的：
`$1^{\infty}$` 由一个数字、一个上标和一个符号组成，早期版本把 `\infty` 归进结构命令，
于是这个「未定式标记」被做成了公式卡，而它的注解句跟同一节课的易错点卡**一字不差**——
印出来是两张废纸。靠长度阈值也拦不住：写成 `$1^{\infty}$` 有 11 个字符，照样漏过去。

黑板上的东西另收一路：`write_latex` 写下的公式（`tex`）进公式池，`write_steps` 写下的步骤做成一整张**解题步骤卡**——目标当正面、步骤当背面。

后者是补上的：早期版本只从黑板收函数图的表达式，而黑板上**结构最清楚**的内容恰恰是那份「目标 + 有序步骤」，反而完全没收。同一节课里它比任何一段讲解都更适合当复习卡。

黑板公式的背面只放 `note`（老师写在公式下面的那句小字），没有就留空。以前会硬塞一句「在黑板上写下的式子」当注解——那不是语境、是标签，学生复习时读到等于没读。

### 两道去重

规则抽取会从不同角度命中同一句话，所以出了两条去重：

- **背面不跟别处复读**：某张卡的背面如果跟别的卡的正面（或背面）是同一句，背面清空。
  清的是复读，不是删卡——卡本身还有价值。
- **公式清单不再拆卡**：如果某张卡整个就是「一串并列公式的清单」（剥掉 `$...$` 后不剩
  文字），那它列到的公式就不再单独出卡。否则「必记 2」加三个等价无穷小会变成四张卡，
  翻的时候会觉得这工具在凑数。两个约束缺一不可：**至少两个并列公式**才叫清单（整节课
  只讲一个公式时，那张结论卡也是纯公式，但公式卡不该被一起干掉）；**剥掉公式后还剩
  文字**说明有语境（「记住：…，这就是第二个重要极限」），这种卡提到的公式该单独留一张。

### 两条生成路径

| 方式 | 成本 | 特点 |
| --- | --- | --- |
| **整理成复习卡片**（默认） | **0 次调用** | 本地规则抽取，即时、离线可用、可重复跑（同内容不会重复出卡） |
| **AI 精炼** | 1 次调用 | 让模型重新组织，把易错点的「错误说法 / 正确理解」拆得更干净。会覆盖当前卡片，有确认 |

先用免费的，不满意再花那一次调用。

### 导出

- **导出 PDF** —— 调浏览器打印，在打印对话框里选「另存为 PDF」。
  A4 两栏、按类型配色、卡片带 `break-inside: avoid` 不会被分页切成两半。
  **这一步需要你在打印对话框点一下**：零依赖的纯前端拿不到浏览器的 PDF 引擎，
  而自己在 JS 里造 PDF 就得内嵌中文字体（几 MB），那会毁掉这个项目最大的优点。
- **下载 HTML** —— 一个自包含的 `.html`，样式内联、双击就能打开再打印一次，适合存档。

屏幕上的卡片、打印出来的卡片、下载的 HTML —— **同一套 HTML、同一套 CSS**（`cards.js` 里的
`CARD_CSS`，字号用 `em`，屏幕 13.5px / 打印 10pt）。所以「所见即所得」不是靠对齐两份模板，
而是根本只有一份。

> 公式在**无外网**时会退化成等宽的 LaTeX 原文（跟全站一致的降级策略）。
> 有网时 KaTeX 正常渲染。数学内容宁可显示原文，也不做有损的自动美化。

## 学习引擎 v2：每个机制都对应一个具体的放弃原因

「学习主动性」和「知识趣味性」不是靠加动画、加 emoji、加积分飘字能解决的。
真正让人半途而废的是几个很具体的时刻，所以这里逐个对着它们设计 ——
机制全部借鉴成熟开源项目的既有做法，不是自创。

| 放弃的时刻 | 机制 | 来源 |
| --- | --- | --- |
| 打开应用不知道先干嘛，于是关掉 | **「现在只做这一件事」**：按「遗忘风险 × 考试紧迫度」加权排序，**只返回一个**建议 | [orbit](https://github.com/andymatuschak/orbit) 的「可编程注意力」——注意力是可编排的资源 |
| 反复刷同一道简单题，感觉在学其实没学 | **三级掌握度**（未学 / 学习中 / 熟练 / 精通）。精通要求「该节点下**每道题**都答对过」，只刷同一道题三次只会停在「熟练」 | [helix-trainer](https://github.com/bug-ops/helix-trainer) 的 Scenario Mastery |
| 刷分刷到没意义，做题变成刷数字 | **XP 递减**：掌握度 ×0.5/×0.2，同日重复第 2-3 次 ×0.7、第 4 次起 ×0.3，两个乘数相乘、下限 1 分。界面会写明「该知识点已精通」而不是只显示 `+2` | 同上（XP 倍率 + 当日衰减） |
| 断一天打卡，觉得「反正已经断了」，彻底放弃 | **补签券**：每周 2 张，只补「昨天」且前天必须真打过卡；券不累积。连续链不断，但也不是免死金牌 | Duolingo / HabitTrove 的 streak freeze |
| 「还剩 60 个知识点」听着很多，于是一直拖 | **备考进度投影**：按最近 14 天日均新学速度，算出考前能覆盖多少、还差多少个、每天该推几个。来不及这件事越早暴露越有救 | —— |
| 只有几分钟碎片时间，觉得「这点时间学不了」 | **闪电战**：60 秒、3 条命、连击倍率最高 ×5，抽题**优先推薄弱知识点** | helix-trainer 的 Arcade 模式 |
| 公式记不住，因为从没见过它长什么样 | **公式实验室**：4 个可拖可玩的模块，拖滑块时 Canvas 实时重绘，最后给一句大白话结论 | [mathlearn](https://github.com/joeseesun/mathlearn) 的 Explorable Explanations |
| 答完题看解析，看到的是一堆反斜杠 | 解析统一过 `inlineMd()`（自动 LaTeX 包裹 + 行内公式渲染，但不加 `<p>` 包裹）。**204 条解析里 132 条带 LaTeX**，之前这些全是裸源码 | —— |
| 答对答错没有即时反馈，做题像填表 | 零依赖 WebAudio 程序化音效，连击越高音越高 | mathlearn（纯合成，不加载音频文件） |

几条刻意的取舍：

- **精通口径从严**。不用「最近三次全对」这种更松的判据 —— 那样刷节点里最简单的那道题三次就能「精通」，正是要防的事。
- **补签只补昨天**。断两天以上就该真的从头来，否则券会消解连续打卡本身的意义。
- **音效默认跟随系统「减少动态效果」**，且任何一步失败都静默降级 —— 音效永远不该影响主流程。
- **公式实验室的数学层与绘图层分开**。纯数学函数（割线/差分/黎曼和/辛普森/泰勒/ε-N）不碰 DOM，可以单独测数值；
  画布只负责把结果画出来。这样「公式算错了」和「图画歪了」是两类可分别定位的问题。

它也顺手证明了**截图不能被断言替代**：分页那 18 项断言全绿的时候，导航其实是挤在一行里、
「等价代换的应用」被截成「等价…」—— **断言测的是行为，不是够不够看**。
（现在改成标题一行、控件一行。）

`tests/smoke-online.js` 是**线上冒烟**（**不进测试套件**，需要联网）：

```bash
node tests/smoke-online.js                          # 默认打 GitHub Pages
node tests/smoke-online.js http://localhost:8080/   # 也可以打本地
```

它存在的理由：`curl` 只能证明「文件在服务器上」，证明不了「页面跑得起来」。
GitHub Pages 上脚本 404、加载顺序错、KaTeX CDN 挂掉，都会让 `curl` 全绿而页面白屏。
所以它开真浏览器、走真网络、抓真报错，逐项验 60 条：脚本装载与全局 API、无障碍骨架、
答题反馈的播报区、图表文字摘要、设置页两个新面板、**诊断包不含敏感字段**（拿线上真跑一遍）、
375×812 五个路由无横向溢出、抽屉开合与 Esc 闭环、**写盘失败横幅的出现与自动撤销**、
以及控制台 0 报错 + 无 4xx/5xx。

两个踩过的坑写在这里，免得下次再踩：

- **断言必须下在有内容的档上**。空档下统计页是空态、答题页可能不出题，断言会「因为没东西可比」
  而假通过或假失败。所以脚本第一步就是播种 96 条作答记录。
- **别在错误的页面上数元素**。`#blitz-feedback` 只在闪电战开局后才渲染，`#qbody-*` 只在答题页才有 ——
  在仪表盘上数 `[aria-live]` 只会得到 1（那个 toast），然后误判成「无障碍没做」。

`test-browser` 找不到 Chromium 会自动跳过（不算失败）。它做了几件不那么显然的事：

- **掐掉 KaTeX 的 CDN 依赖**——否则没网时那个请求一直挂着，`readyState` 永远停在 `loading`，
  测的就成了网络而不是代码。
- **把 `window.print` 换掉**再调导出，并切到 `Emulation.setEmulatedMedia('print')`
  断言 `#app` 真的被隐藏、打印容器真的变成两栏网格——这样不用弹打印对话框也能验证打印样式。
- **真去数画布上的非透明像素**。`document.querySelector('canvas')` 返回了元素、样式也对，
  但画布一片空白 —— 这是最常见的「假通过」，只有数像素能抓到。
- **断言「没有裸露的 LaTeX」而不是「没有反斜杠」**。冒烟页的 KaTeX 是桩，桩会把原始 tex
  放进自己的 span 里，所以判据是「剔除渲染过的片段之后，外面不能再有反斜杠」。

`test-css-coverage` 是为了治一类特定的坑：**JS 里写了 `class="xxx"`，`style.css` 里没有 `.xxx`**。
页面不报错、测试全绿、截图看不出，只是那一块裸奔。它把两种 `class` 属性分开处理 ——
纯字面量的必须精确匹配，拼接模板（`class="a' + (x ? ' b' : '') + '"`）只取第一个 `'` 之前的前导字面量，
因为引号里面的东西分不清是类名还是 JS 里的比较值（`kind === 'cloud'` 里的 `cloud` 就不是类名）。

## 判题容错

选择题精确匹配；填空题支持：全半角与全角标点归一、`1/2` 与 `0.5` 等价、π/pi/`\pi` 互认、`x^2` 与 `x²` 归一、数值 1e-6 容差。

## 已知限制（MVP 边界）

- **无账号体系，也没有云端副本**。数据只在这台浏览器里；换浏览器 / 清缓存 / 重装系统都会让它消失。
  所以设置页有「数据与备份」：导出 JSON、合并导入、覆盖导入，并显示存储用量与上次备份时间
  （超过 14 天没备份且累计作答 ≥20 次时会显式提醒）。**没有自动备份**，需要自己点。
- 存档体积是**有上限**的：`attempts` 明细保留最近 2000 条，更早的只保留聚合计数。
  因此错题本里很久以前的「我的答案」原文会显示为「记录已归档」——计数与掌握度不受影响。
- 诊断信息**不会自动上报**，需要用户主动复制或导出。`Telemetry.endpoint` 目前留空。
- 无障碍覆盖到「键盘可达 + 读屏器可读」这一层（跳过导航、焦点环、图表文字摘要、live region），
  但**没有做过专业读屏器实测**（NVDA / VoiceOver 逐页走查），也没有做 WCAG 等级认证。
- 小屏做了抽屉化与单栏堆叠（375px 实测无横向溢出），但**没有做平板专门布局**，
  也没有针对超长公式的手势缩放。
- 内置题库 204 题（覆盖 68 个考点、每节点 ≥2 题），含来源标注（经典例题/真题改编/模拟题 + 年份）；可在设置页按来源/年份/难度筛选练习
- 验收从当前考点加权抽 3 题（真题改编优先、难度贴近考点难度）
- 公式实验室目前 4 个模块（割线→切线 / 黎曼和 / 泰勒展开 / 数列 ε-N），定位是「把公式拖出来看一眼」，不是完整图形计算器
- 闪电战从内置 204 题里抽（按薄弱优先排序），不生成新题；单局上限 80 题
- KaTeX 走 `cdn.jsdelivr.net`，**是外部单点**（大陆网络下 jsDelivr 曾长期不可达）。
  加载失败时公式会退化成源码，设置页「诊断」里会显示「公式渲染器未加载」。彻底解决需要把 KaTeX 本地化。
- 未实现 V2.0 路线图中的多设备同步、语音交互、AI 生成个性化题目（详见开发文档路线图）

## 设计取向

界面刻意避开「AI 生成感」，走**学术出版物**路线，而不是常见的 SaaS 仪表盘路线。

**要解决的问题**：早期版本带着一套典型的 AI 生成 UI 特征——紫蓝渐变、emoji 当图标、统一 8px 大圆角、一个大阴影复用到底、`transition: all`、一排三个一模一样的卡片。这类界面单看还行，用久了信息密度低、层级靠装饰而不是靠排版撑起来，长时间读公式很累。

**借鉴对象与取用点**：

| 来源 | 借鉴的是 |
| --- | --- |
| Anki / Obsidian | 去装饰化——颜色只承担语义、不承担美观；高信息密度优先于留白 |
| Linear | 用 1px 边框代替投影做卡片分隔；全站单一强调色；紧凑的纵向节奏 |
| Radix Colors | 12 步色阶的语义分层——1–2 背景 / 3–5 组件背景 / 6–8 边框 / 9–10 实色 / 11–12 文字 |
| 学术出版物排版 | 数学正文走衬线（Georgia + 宋体族），界面文字走无衬线；数字用 `tabular-nums` 对齐 |

**落地的具体规则**：

- **配色**：暖灰纸感底色 `#f6f6f3` 替代冷蓝；全站唯一强调色是学术墨蓝 `#1b4d8f`，悬停时**加深**（`#143a6b`）而不是变亮或转紫
- **形状**：圆角收敛到 6px（小控件 4px），投影只保留 `0 1px 2px rgba(26,26,23,.05)` 这一档
- **图标**：所有图标统一 24×24 viewBox + 1.5px 描边的线性风格，内联 SVG；**全站零 emoji**（成就墙改用「印章」式单字块）
- **排版**：标题层级严格递减；数学内容（题干、公式、卡片正面）走衬线族
- **动效**：只动 `background` / `border-color` / `opacity`，不用 `transition: all`
- **布局**：知识树从单列 3000px 长条改为**多列网格**，一屏可见完整结构；学习热力图改为 GitHub 贡献图布局（一列一周、一行一天）

> 这几条不是靠自觉维持的：`test-css-coverage.js` 会扫一遍新增样式，出现渐变、`transition: all`、
> 超过 9px 的圆角、或设计系统之外的色值就直接失败。新增页面（公式实验室、闪电战）也走同一套规则 ——
> 「只有焦点卡是蓝的」用来抢注意力，而不是靠变大、变圆、发光。

**顺带修掉的两个真实缺陷**（与视觉重构无关，同批发现）：

- 复习卡正面原来先渲染 KaTeX 再剥 HTML 标签取摘要，会把公式的无障碍层与视觉层剥成重复乱码（`limx→o3x2x|…`）。改为在**原始 Markdown 文本**上截断，并保证 `$` 配对不被打断
- 复习队列「今日已评」显示的是队列总数，第 1 张就显示全部；改为 `已评 n / 总数`

## 技术栈

- 前端：原生 JavaScript（ES5 兼容）+ 原生 CSS
- 数学公式：KaTeX（CDN 加载，离线自动降级）
- 图表：纯 SVG + CSS 动画，无图表库依赖
- 数据存储：localStorage（浏览器本地持久化）
- 存档层：`js/store.js` —— 全量聚合 + 明细裁剪 + 配额探测 + 导出/导入，零第三方依赖
- 可观测性：`js/telemetry.js` —— 本机事件与错误环形缓冲，零第三方依赖，默认不外发
- 测试：Node 内置模块（`http` / `child_process` / 内置 `WebSocket`），零测试框架
- 零构建、零 npm 依赖，任何浏览器打开 `index.html` 即可运行
