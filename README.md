# 研数 · 考研数学 AI 自学系统

根据《考研数学AI自学系统开发文档 v1.0》实现的**单人本地 MVP**：每天和 AI 老师聊着学完知识点，智能出题验收，答错的题自动进错题本并按 SM-2 间隔重复调度复习，每日任务 + 专注计时自动打卡。

技术形态：**纯前端多文件应用**（原生 JS + CSS，零构建、零依赖、零后端）。

---

## 快速开始

**方式一：直接双击**（推荐，完全离线可用）

打开 `index.html`，浏览器以 `file://` 协议运行，所有数据存本机浏览器 localStorage。

> 数学公式默认走 KaTeX CDN，无外网时自动降级为高亮原文显示，不影响功能。
>
> **默认接云端 API（DeepSeek）**，`file://` 下也能用——去设置页填一个 Key 就行。
> 想改用本地大模型（LM Studio / Ollama）请用方式二，`file://` 协议下浏览器会拦截对 `localhost` 的请求。

**方式二：本地服务器**

```bash
cd kaoyan-math-tutor
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080
```

**方式三：GitHub Pages 在线部署**

本仓库可直接推送至 GitHub 并开启 GitHub Pages（Settings → Pages → Branch `main` / folder `root`），即可获得免费在线访问地址，手机/平板无需安装即用。

## 打卡规则

满足其一即视为当日打卡成功（进入连续天数与热力图统计）：

- 今日任务单 3 类任务全部完成（复习卡全评 + 新知识点全验收 + 每日一练全作答）
- 专注计时累计 ≥ 30 分钟

## AI 老师：Agent 内核

聊天页的 AI 不是"关键词匹配 + 写死模板"，而是一个带工具的 agent loop。

**它能看到什么**：每次对话前，系统从 localStorage 实时算出你的学情并注入提示词——已掌握/学习中/未开始考点数、连续打卡天数、近 7 天正确率、最薄弱的几个考点及错误次数、当前考点的作答历史与待攻克错题。模型据此决定讲什么、讲多深。

**它能做什么**（9 个工具，全部读写你的真实数据）：

| 工具 | 作用 |
| --- | --- |
| `query_weakness` | 查最薄弱的考点排行 |
| `get_mistakes` | 翻错题本（答错且尚未做对的题） |
| `pick_question` | 按知识点 + 难度加权抽题 |
| `get_node` | 读某个考点的完整正文与关联考点 |
| `search_nodes` | 按关键词检索知识树 |
| `get_progress` | 读整体进度、打卡、距考试天数 |
| `draw_graph` | **把函数画成图像直接显示**（讲极限/单调性/凹凸性/面积时） |
| `save_note` | 把总结记到考点下 |
| `mark_mastered` | 标记已掌握并生成复习卡片 |

`draw_graph` 配了一个自写的递归下降表达式求值器（**不使用 eval**），支持 `+ - * / ^`、括号、隐式乘法（`2x`、`3sin(x)`）、`sin/cos/tan/ln/log/exp/sqrt/abs` 等函数与 `pi`、`e` 常数，输出纯 SVG 曲线，无图表库依赖。

**四种老师人设**（设置页切换，同一内核的不同提示词策略）：严格督学 / 段子手 / 苏格拉底 / 应试机器。

**模型通道**：

- **本地模型（推荐）**：设置页点"探测本机"自动扫描 LM Studio（1234）、Ollama（11434）、vLLM（8000）、llama.cpp（8081）。免 Key、离线、数据不出本机。
- **云端 API**：兼容 OpenAI 协议（DeepSeek / Kimi / 通义）。Key 仅存内存，不写入 localStorage。

**两条健壮性保障**：

1. 模型不支持原生 `tools` 参数（本地小模型常见）时，自动降级为**文本工具协议**（` ```tool ` 代码块），不必换模型。
2. 模型完全不可用时，静默降级回内置教学引擎，聊天不中断。

> **注意**：默认的云端通道在 `file://` 下可直接用。只有改用**本地模型**时才需要方式二——`file://` 协议会拦截对 `localhost` 的请求，请在该目录执行 `python3 -m http.server 8080` 后访问 `http://localhost:8080`；LM Studio 需在 Server 设置中开启 CORS。

## 讨论模式：老师 + 三个学生

在知识点页点「开一局讨论」，换一种学法。三个学生水平不同，围绕一道**你做错过的题**掰扯一轮，最后老师点名点评。

**角色不是靠提示词里的形容词区分的**——那样模型会趋同，三个人说出同一种 AI 腔。差异化靠三样东西：

| 角色 | 掌握的信息 | 典型表现 |
| --- | --- | --- |
| 学生甲（思路快） | 完整正文 + 例题 + 关联考点 | 一针见血，爱把规律总结成一句话 |
| 学生乙（中等） | 正文 + 例题 | 跟得上，但爱追问"为什么" |
| 学生丙（基础薄弱） | **只有第一句定义** | 口语化、用错术语、想当然 |

信息量递减 → 必然产生分歧。更关键的是：**丙犯的错从你的错题本和题目干扰项里挖**，不是模型随机编的。所以他踩的坑，就是你真的会踩的坑。

**一轮流程**：老师抛题 → 甲发言 → 乙追问 → 丙暴露误解 → 甲纠正丙 → 老师点名点评（谁对、谁错在哪一步、这个考点必记的 2-3 条结论）。

**你可以随时插话**，老师会停下来直接回应你，再继续讨论。

**生成成本**：老师那两段是真调用（吃你的真实学情），三个学生的发言一次生成。整场 **2 次模型调用**，本地模型约 8-15 秒，用逐字打字掩盖等待。

**选题优先级**：错过次数最多的题 → 正确率最低的考点里抽一题 → 当前考点随机一题。

## 判题容错

选择题精确匹配；填空题支持：全半角与全角标点归一、`1/2` 与 `0.5` 等价、π/pi/`\pi` 互认、`x^2` 与 `x²` 归一、数值 1e-6 容差。

## 已知限制（MVP 边界）

- 无账号体系，数据跟随浏览器（换浏览器/清缓存即重置，可在设置页导出数据前先备份思路）
- 内置题库 204 题（覆盖 68 个考点、每节点 ≥2 题），含来源标注（经典例题/真题改编/模拟题 + 年份）；可在设置页按来源/年份/难度筛选练习
- 验收从当前考点加权抽 3 题（真题改编优先、难度贴近考点难度）
- 未实现 V2.0 路线图中的多设备同步、语音交互、AI 生成个性化题目（详见开发文档路线图）
