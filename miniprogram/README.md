# 研数 · 微信小程序

Web 端的第二个客户端。后端完全复用，没有第二套业务逻辑 ——
小程序只是换了一种「怎么显示公式」和「怎么登录」。

---

## 跑起来

```bash
# 1. 起服务端（在仓库根目录）
npm run check      # 类型检查 + 构建前端（控制台页面在这里面）
npm run start      # http://127.0.0.1:5180

# 2. 用微信开发者工具打开本目录
#    导入项目 → 选择 miniprogram/ → AppID 填「测试号」即可
```

**必做的一步**：开发者工具 →「详情」→「本地设置」→ 勾上
**「不校验合法域名、web-view、TLS 版本以及 HTTPS 证书」**。

不勾的话所有请求会被拦掉，报错是「不在以下 request 合法域名列表中」——
这句话看起来像网络问题，实际是域名白名单问题，会浪费很久。

服务端地址在 `config.ts` 的 `BASE_URL`，本地开发默认 `http://127.0.0.1:5180`。

---

## 三种运行环境的地址

| 场景 | BASE_URL | 额外要求 |
|---|---|---|
| 开发者工具 | `http://127.0.0.1:5180` | 勾「不校验合法域名」 |
| 真机预览 | `http://<电脑局域网IP>:5180` | 服务端 `HOST=0.0.0.0`；同一 WiFi；同样勾不校验 |
| 正式发布 | `https://你的域名` | **HTTPS + ICP 备案**，并在公众平台配进 request 合法域名 |

最后一行是硬门槛：**个人主体也要备案**。域名没备案的话，只能停在
开发者工具和真机预览，发布不了。这条没有变通办法。

（微信云托管的默认域名可以绕过备案，但 SQLite 要挂持久卷，
反而比备案一台国内轻量云更麻烦。）

## 登录

只有一条路：`wx.login` → `code` → `POST /api/app/wx-login` → 会话 token。

服务端把 openid 映射到一个 users 行（邮箱是合成的
`wx_<hash>@wx.local`，因为 `users.email` 是 NOT NULL）。

**本地没有小程序 AppID 时**，用开发旁路：

```bash
WX_DEV_LOGIN=1 npm run start
```

打开后 `code` 会被直接当成 openid。⚠️ 这等于「任何人可以用任意字符串
登录成任意账号」，**只允许本地开发**。控制台的「环境自检」会在它打开时
挂一条红色错误，防止忘了关。

有 AppID 之后改成：

```bash
WX_APPID=wx... WX_SECRET=... npm run start
```

## 公式怎么办（这是小程序最麻烦的地方）

小程序没有 DOM、加载不了 KaTeX 的 25 个字体文件，所以 KaTeX 那套
HTML 输出塞进 `rich-text` 一定是错位的乱码。

方案：**服务端 MathJax tex2svg → resvg 转 PNG**，前端只管显示。

```
文本 "设 $f(x)=x^2$ 连续"
  → POST /api/render/text
  → segments: [
      { type: 'text', v: '设 ' },
      { type: 'math', url: '/math/abc123.png', w: 110, h: 35 },
      { type: 'text', v: ' 连续' }
    ]
  → <math-text segments="{{...}}" />
```

几个关键点：

- **切段而不是整段出图**：文字部分仍是原生 `<text>`，可选中、可复制、
  可被读屏软件读到。整段出图等于把题变成一张图片。
- **一次请求渲一批**：一道题是题干 + 4 选项 + 解析，逐条请求在弱网下
  要等好几秒。
- **必须传 `color`**：MathJax 的字形是 `currentColor`，光栅化时没有父元素
  可继承 → 一律变黑。深色主题下就是一张「透明底黑字」，等于看不见。
  `config.ts` 的 `INK` 要和 `app.wxss` 的 `--fg` 保持一致。
- **字号必须对齐**：服务端 `renderMath.js` 的 `FONT_PX`（17）
  和 `components/math-text/index.wxss` 里 `.mt` 的 `font-size` 要一样。
  改一处必须改另一处，并且清掉 `server/.cache/math`（缓存键里没有字号）。
- **`<image>` 加载网络图片不受合法域名限制**，所以公式图不需要额外
  配 downloadFile 域名 —— 只有 `wx.request` 受限。

## 类型检查

```bash
npm run typecheck:mini     # 在仓库根目录跑
```

`tsconfig.json` 用的是 `strict: true` + `miniprogram-api-typings`（官方类型包，
装在仓库根的 devDependencies，所以 `miniprogram/` 目录本身保持干净，
微信开发者工具不会把它当成 npm 项目）。

**为什么必须有这一步**：这 14 个 `.ts` 文件以前零检查 —— 微信开发者工具
只在打开项目时编译，CI 里跑不到。第一次接上 tsc 就抓出 5 个错误，其中
两个是「类型撒谎」：

| 位置 | 声明的类型 | 实际存的 | 后果 |
|---|---|---|---|
| `today` 的 `quizDots` | `boolean[]` | `{i,on}[]` | 不崩，但后来的人按类型改 `item ? ...` 就静默失效 |
| `quiz` 的 `optSegs` | `Segment[]` | `Segment[][]` | 同上 |
| `fetchDue` 的返回 | `{cards, total}` | `{cards, today, count}` | 有人按类型读 `.total` 就永远得到 0 |

还有一处真陷阱：`RequestOptions.method` 声明了 `PATCH`，但
**`wx.request` 不支持 PATCH**（合法值只有 OPTIONS/GET/HEAD/POST/PUT/
DELETE/TRACE/CONNECT）。写成 PATCH 时类型能过，运行时会被当成 GET
或直接失败 —— 而开发者工具里不一定看得出来。服务端所有更新接口用 PUT，
所以这个选项直接删掉了。

CI 里拆成两个独立步骤（`类型检查（Web）` / `类型检查（小程序）`），
挂了能一眼看出是哪一端。

### 拍照识别

三个入口都在「我的」页：

- **拍照解题**：拍一道不会的题 → AI 转录 + 完整解答 → 分步展开
- **拍照录题**：拍纸质题 → AI 识别题干/选项/答案/解析 → 一键生成复习卡片
- **拍照整理笔记**：拍手写笔记 → AI 整理成结构化知识点 → 复制或生成卡片

为什么用 `uploadFile` 而不是 base64 POST：手机拍照 1~3MB，base64 后 1.3~4MB，
JSON body 太大容易超时。uploadFile 走 multipart，更稳定。

服务端用 `@fastify/multipart` 接收图片，转 base64 后发给多模态模型
（deepseek-chat、gpt-4o、claude-3 等）。控制台可以单独配 `visionModel`，
和文本模型用同一个 base/key，只覆盖 model 名。

**解题结果默认收起完整解答**：只先给「这题考什么 + 关键那一步」，
步骤要点一下才展开。产品里所有「看答案」的地方都遵守同一条规则 ——
复习页答案默认收起、答题页提交后才出解析。一上来就摊开六步推导的话，
用户的眼睛会直接跳到答案，那道题就白拍了。

**防幻觉是解题功能的底线**：提示词里写死了「看不清的地方写（字迹不清），
绝对不要猜测或补全题目条件」。模型在模糊图片上的默认行为是编一个
「看起来合理」的条件然后认真解它 —— 用户会拿到一份工整、完整、
逻辑自洽、但解的是另一道题的解答。`tests/ai-solve.mjs` 用断言钉住了这条。

**结构化输出的降级**：模型吐的 JSON 解析不出来时，不报错，把原文塞进
`question` 字段并标 `degraded: true`，前端显示「格式异常」+ 原文。
用户至少能看到内容，而不是面对一个空白页。

**公式渲染**：解题结果里的每个字段都走 `renderTexts` 批量渲一次。
模型经常把 `steps.f` 写成不带 `$` 的裸 LaTeX，服务端 `sanitizeSolve`
会补上定界符（只补「含命令且不含中文」的）；反过来，纯数字的 `$3$`
会被剥成 `3` —— 因为 `renderMath.js` 的 `looksLikeMath` 把纯数字判成
「多半是金额」不渲染，留着 `$` 用户会看到带美元符号的答案。

### 连续练习

从「题库」或「错题本」点「去做这道题」时，会把**后面所有题目 id 一起带过去**。
答题页底部因此多了一颗「下一题」按钮，答完直接 redirectTo 到下一张 ——
不用回列表再点一次。

用 `redirectTo` 而不是 `navigateTo`：连做 20 道题时，后者会把 20 个页面
压在栈里，按返回键要按 20 次。

### 错题本

接口返回的错题已经带着「上次答的是什么」，所以这一页能就地展开讲清楚，
不用再跳进答题页才能看到解析。

顶部做了一条知识点筛选条：同一个知识点连续错了 3 次，说明前置概念没搞懂，
不是这道题的问题。筛出来集中看，比按时间线扫更有效。

### 答题流程

一个页面 + 六个题型分支，不是六个页面。题干、选项、解析、判分反馈完全共用。

**客观题**（选择 / 多选 / 判断 / 填空）：提交 → 服务端判分 → 出结果。
**解答 / 证明题**走**两步**：

1. 第一次提交只把参考答案和评分点亮出来，服务端**不记账**（返回 `selfGrade: true`）
2. 用户对照评分点自评「做对了 / 做错了」，第二次提交才真正记账

为什么必须两步：解答题没法自动判分。让 AI 判要花配额、还可能判错；
用户自己对照评分点最准，也是 Web 端的做法。

计时从进页面开始，提交时上报秒数（服务端截断到 0~3600）。
同样答对，20 秒和 3 分钟说明的掌握程度完全不同 —— 这个数据存进
`attempts.seconds`。

### 界面口径：炭与纸

**底色是炭（`#131417`），字是纸白（`#e9e6df`），强调色只有一个：琥珀（`#c9973f`）。**
叙事是「夜里台灯下的演算纸」——考研的人多半在晚上学，屏幕要能看两小时不累眼。
琥珀只出现在主按钮、进度条、连击火苗上；其余全靠灰阶层级和字重。

#### 为什么换掉了原来的「深空 + 青紫」

原来的配色是近黑底 + 青色 + 紫色，外加顶部径向渐变光晕、按钮上的青色发光、
数字上的青色 text-shadow。这套组合有个共同的名字：**AI 默认款**。

用 [impeccable](https://github.com/pbakaus/impeccable) 的确定性检测器扫真实渲染，
一次报出 **26 个反模式**：

| 规则 | 命中 | 说明 |
|---|---|---|
| `low-contrast` | 8 | 最差一处 1.1:1（白字压青底），3 处弱文字在 3.3~3.8:1 |
| `undersized-ui-text` | 15 | tabBar 文字 10px，低于 11px 下限 |
| `dark-glow` | 2 | 青色 text-shadow + box-shadow |
| `ai-color-palette` | 1 | 紫/青配色 |

重构后同样的扫描是 **0**。

#### 三条硬约束（都是踩出来的）

1. **卡片用实体色，不用半透明白**。原来 `--card` 是 `rgba(255,255,255,0.042)`，
   叠在带光晕的背景上，同一张卡片在不同位置的对比度会飘 —— 检测器因此报出
   3.3:1 和 3.8:1 两个不同的值。现在卡片是 `#1b1d21` 实色，对比度恒定。
2. **不写彩色阴影**。发光是 AI 味的另一半，删干净。
3. **最小字号 22rpx（11px）**。再小是可读性问题，不是风格问题。

#### 色板（对比度逐个验过，最低 4.60:1）

```
--fg        #e9e6df  on #131417 → 14.78:1
--fg-soft   #b3aea4  on #131417 →  8.34:1
--fg-mute   #918c82  on #22252a →  4.60:1   ← 最紧的一处（药丸底）
--accent    #c9973f  on #131417 →  7.00:1
按钮文字     #1a1408  on #c9973f →  6.96:1
```

`--fg-mute` 是从 `#8a857b` 提上来的：它在 `#1f2228` 的主卡上只有 4.34:1。
提亮比压暗卡片更省事，也没有削弱灰阶层级。

#### 页面上的数据可视化

**数据早就在了，只是页面没用。** `/api/study/stats` 一直返回
`trend`（14 天）/ `heatmap`（182 天）/ `radar`（三科）/ `masteryDist` /
`chapters`，而今日页只用了 `snapshot` 里那几个数 —— 结果是一屏只有
一个大数字，下面三张长得一样的卡片。

现在：

| 页面 | 图形 | 回答的问题 |
|---|---|---|
| 今日 | 进度环（已做 / 已做+还剩） | 今天还差多少 |
| 今日 | 本周柱状图（7 天） | 这周有没有断 |
| 今日 | 三科掌握度条（分类色） | 哪科最弱 |
| 我的 | 近两周柱状图（14 天） | 这两周在往上还是往下 |
| 题库 | 难度分布（5 档） | 这个题库难不难 |

四条约定：

1. **柱高按区间最大值归一，不用固定上限**。固定上限会让「每天做 8 题」
   的人七根一样高，他的努力在图上完全看不见。
2. **没数据的那天留一个底座**（6~8% 高度）。整根消失看起来像「这格坏了」，
   不像「这天没学」。
3. **格子里不写数字**。试过热力图里写题数，但中间两档两头都不够
   （42% 档配浅字 3.48:1、66% 档配深字 3.86:1），过不了 4.5。
   格子的作用是「一眼看出趋势」，不是精确读数。
4. **分类色来自考点分类本身**（`server/src/data/categories.json`），
   不是随手挑的装饰色。但那里存的是给深色 Web 端用的暗色
   （高数 `#1b4d8f` 在卡片上只有 2.01:1），要按同色相提亮一档再用。

#### 怎么复现这次审计

`detect` 对 `.wxml/.wxss` 只做 regex，元素级规则（对比度、字号、嵌套卡片）
全都跑不了。要把真实样式渲染成 HTML 再扫：

```bash
node .audit.mjs                                    # 生成 /tmp/audit/mini.html
npx impeccable detect /tmp/audit/mini.html --viewport 375x812
npx impeccable detect --list-rules                 # 看全部 62 条规则
```

`.audit.mjs` 把 wxss 的 rpx÷2 转成 px，配手写 HTML 结构（和 wxml 同构）。
**改 wxml 结构时要同步改这个脚本**，否则审计的是旧布局 —— 这次就踩过：
把「我的」页的三个图标改成列表后，脚本里还是旧的三列结构，截图出来是错乱的。

#### 其他

tabBar 图标不是引第三方图标库，而是用 SVG 现渲染的 81×81 PNG
（见 `assets/tabbar/`）—— 少一个依赖，颜色也能跟着主题改。

## 推送

服务端 `server/src/lib/push.js` 每 10 分钟看一次「现在是不是 `push.hour` 点」，
是就扫一遍该推的人：**有到期卡 + 授权过 + 还有额度 + 账号是 active**。

四个条件缺一不可。微信的订阅消息是**一次性**的 —— 用户点一次允许只能收一条，
推成功就减一条 `push_sub.quota_left`，减到 0 就得重新授权。

模板字段名（`thing1` / `time2`…）由你在公众平台选的那个模板决定，代码猜不出来。
所以在控制台「订阅消息」里配 `payload`，支持占位符 `{due}` `{streak}` `{date}` `{time}` `{name}`。

验证：控制台点「试跑」（dryRun）先看会推给几个人，再点「立即推送」。
字段名填错时微信返回 `errcode 47003`，那句话完全看不出是字段名的问题。

## 已知缺口

1. **登录注册全部走微信**。网页端仍然保留邮箱+密码，两边的账号是分开的 ——
   按你的决定，不做绑定。
2. **8 套主题只搬了深空**：其余主题在 Web 端的 `styles/index.css`，
   要按同样色值抄到 `theme.wxss`，并按 `--fg` 决定公式墨色。
3. **小程序端没有单元测试**。现在的保障是三样：`typecheck:mini` 的类型检查、
   上面那个「模板绑定 / class 覆盖率」静态脚本、以及真浏览器截图验证。
   这三样能抓住「点了没反应」「样式丢失」「类型对不上」，但抓不住
   「算错了」—— 比如复习页的四档评分映射。要补的话，得先把纯逻辑
   （评分映射、进度计算）抽成独立模块，才能在 Node 里测。
4. **域名 ICP 备案**。发布硬门槛，技术层面已经就绪。
